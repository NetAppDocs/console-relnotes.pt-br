=== Backup e Recuperação



==== Aprimoramentos de cargas de trabalho do Kubernetes

Nesta versão, o NetApp Backup and Recovery apresenta os seguintes aprimoramentos para workloads do Kubernetes:

* *Trident Protect 26.10*: Esta versão inclui Trident Protect 26.10.
* *Suporte aos drivers ontap-nas-economy e ontap-san-economy*: agora você pode proteger reivindicações de volume persistente (PVCs) provisionadas pelo driver NetApp Trident `ontap-nas-economy` (Qtrees) e pelo `ontap-san-economy` driver (LUNs). Ao proteger PVCs usando drivers economy, todo o FlexVol ou LUN subjacente é protegido. Você pode restaurar PVCs individuais a partir desses backups.
* *Alertas compatíveis com Kubernetes*: O NetApp Console agora envia alertas do Kubernetes uma vez por aplicativo do Kubernetes, em vez de uma vez por volume.
* *Suporte a snapshots de grupos de volumes*: agora você pode criar grupos de volumes ao definir uma aplicação Kubernetes. Os grupos de volumes permitem que você crie snapshots de vários volumes juntos como um conjunto consistente com falhas, garantindo a consistência de dados em todos os volumes do grupo.
* *Suporte a storage de objetos compatível com S3*: agora você pode fazer backup de recursos de aplicativos e dados do Kubernetes no storage de objetos compatível com S3 adicionando credenciais de destino de backup e configurando políticas de proteção.


Para obter detalhes sobre como proteger cargas de trabalho do Kubernetes, consulte https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Saiba mais sobre como proteger cargas de trabalho do Kubernetes com NetApp Backup and Recovery"].



==== Aprimoramentos nas cargas de trabalho do ONTAP Volumes

Nesta versão, o NetApp Backup and Recovery apresenta os seguintes aprimoramentos para cargas de trabalho do ONTAP Volumes:

* *Relatórios de proteção*: o NetApp Backup and Recovery agora oferece suporte à criação e ao download de relatórios expandidos para workloads de volumes do ONTAP.
* *Escolha se deseja manter os backups ao cancelar o registro de um sistema ONTAP*: Ao cancelar o registro de um sistema ONTAP no NetApp Backup and Recovery, agora você pode optar por descartar os dados com backup anterior ou mantê-los disponíveis para restauração. A documentação do NetApp Backup and Recovery agora inclui instruções para restaurar os dados mantidos após o cancelamento do registro do sistema.


Para mais detalhes, consulte https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-backup-manage.html#unregister-netapp-backup-and-recovery-for-a-system["Cancelar o registro do Backup and Recovery para um sistema"^].

Para obter detalhes sobre como proteger as cargas de trabalho do ONTAP Volumes, consulte  https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["Saiba mais sobre a proteção de volumes do ONTAP com NetApp Backup e Recuperação"].



==== Aprimoramento das cargas de trabalho do Oracle Database

Nesta versão, nesta versão, o NetApp Backup and Recovery introduz o seguinte aprimoramento para cargas de trabalho do Oracle Database:

*Restauração para um local alternativo*: NetApp Backup and Recovery agora oferece suporte à restauração de um banco de dados Oracle para um local alternativo (um host registrado diferente).

Para obter detalhes sobre como proteger cargas de trabalho do Oracle Database, consulte  https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["Saiba mais sobre como proteger as cargas de trabalho do Oracle Database com NetApp Backup and Recovery"].

[[ransomware-resilience]]
=== Resiliência ao Ransomware



==== Configuração aprimorada do ambiente de recuperação isolado

O Ransomware Resilience agora oferece um fluxo de trabalho aprimorado para a configuração de um ambiente de recuperação isolado. O novo fluxo de trabalho esclarece e simplifica o processo de configuração de um ambiente de recuperação isolado para ambientes em nuvem ou locais.

Para obter mais informações, consulte link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore.html["Crie um ambiente de recuperação isolado para uma restauração limpa"^].



==== Fluxo de trabalho aprimorado para permitir o monitoramento da atividade do usuário

O Ransomware Resilience aprimorou o fluxo de trabalho para habilitar o monitoramento da atividade do usuário. Anteriormente, o Ransomware Resilience testava a conexão do coletor de dados sempre que você habilitava uma estratégia de proteção contra ransomware com monitoramento da atividade do usuário em uma carga de trabalho. Com essa atualização, essa verificação agora é ignorada se houver um coletor de dados para a VM de armazenamento e ele estiver no estado "running", acelerando o fluxo de trabalho de proteção.

Para obter mais informações, consulte link:link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["proteger cargas de trabalho"^].



==== O nível de serviço Flex do Google Cloud NetApp Volumes está geralmente disponível

O suporte ao nível de serviço Flex do Google Cloud NetApp Volumes no Ransomware Resilience agora está disponível para o público em geral (GA).

=== Cloud Volumes ONTAP



==== O Cloud Volumes ONTAP 9.19.1 no Azure

Agora você pode usar o NetApp Console para implantar e gerenciar a versão de Disponibilidade Geral (GA) do Cloud Volumes ONTAP 9.19.1 no Azure.

O Console oferece suporte ao Cloud Volumes ONTAP 9.19.1 na AWS e no Google Cloud desde agosto de 2026.

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Cloud Volumes ONTAP 9.19.1 notas de lançamento"^]



==== Criptografia de host do Azure para o Cloud Volumes ONTAP

A partir do Cloud Volumes ONTAP 9.19.1 GA, a criptografia no host do Azure é habilitada por padrão para novas implantações do Azure de nó único e de alta disponibilidade (HA) que atendam aos pré-requisitos. Esse recurso criptografa os dados no servidor físico que hospeda a VM, incluindo o disco efêmero e os caches associados no nível do host, à medida que os dados são gravados no host e lidos dele.

Antes de implantar o Cloud Volumes ONTAP no Azure, confirme se seu ambiente atende aos seguintes pré-requisitos:

* O  `EncryptionAtHost`recurso está registrado para sua assinatura do Azure. Consulte https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Documentação da Microsoft: habilitar criptografia no host"^].
* O tipo de instância de VM selecionado oferece suporte à criptografia no host na sua região do Azure. Consulte https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Documentação da Microsoft: encontrando tamanhos de VM compatíveis"^].


Observe estes pontos:

* Nenhuma configuração adicional é necessária.
* Se esses pré-requisitos não forem atendidos, a criptografia no host do Azure não será habilitada para sua implantação do Cloud Volumes ONTAP.
* A criptografia no host aplica-se apenas ao Azure, não à AWS ou ao Google Cloud.


Documentação da Microsoft: https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["Use o portal do Azure para habilitar a criptografia completamente usando a criptografia no host"^]



==== Criptografia de rede de back-end nos clusters do Cloud Volumes ONTAP no Azure e no Google Cloud

O Cloud Volumes ONTAP 9.19.1 e versões posteriores oferecem suporte à criptografia de rede do cluster de back-end para configurações de HA no Azure e no Google Cloud.

Habilitar a criptografia de rede do cluster pode afetar o desempenho do cluster. Tenha cautela e verifique se o seu ambiente pode acomodar a sobrecarga adicional antes de habilitar esse recurso.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["Ativar a criptografia de rede de back-end nos clusters do Cloud Volumes ONTAP"^]



==== Capacidade de reduzir interrupções durante a manutenção programada do Azure

Durante a manutenção programada, o Azure pode pausar brevemente uma VM em um par de HA do Cloud Volumes ONTAP. O ONTAP pode interpretar a pausa como uma interrupção do nó e transferir as operações de armazenamento para o nó parceiro, retornando-as quando a VM for retomada (takeover e giveback). Esse processo pode interromper conexões ativas de clientes, mesmo quando não há falha de nó.

Com Cloud Volumes ONTAP 9.19.1 e versões posteriores, você pode habilitar uma configuração opcional que permite que o par de HA continue operando durante um congelamento de manutenção agendada do Azure sem iniciar automaticamente o takeover e o giveback.


NOTE: Este recurso está disponível como uma prévia pública com o Cloud Volumes ONTAP 9.19.1.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["Evite interrupções durante a manutenção do Azure para os pares de HA do Cloud Volumes ONTAP"^]

[[disaster-recovery]]
=== Recuperação de desastres



==== Ordem de inicialização opcional para grupos de recursos do Kubernetes

O NetApp Disaster Recovery agora oferece suporte à configuração opcional da ordem de inicialização para grupos de recursos em um plano de replicação do Kubernetes, especificando uma ordem de prioridade e um tempo de atraso opcional para os recursos. Essa opção permite inicializar recursos ao mesmo tempo quando necessário e atrasar a inicialização de recursos que dependem de outros, ajudando seus aplicativos a voltar a ficar online de forma estável.

Para obter mais informações, consulte link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/drplan-create.html["criar um plano de replicação"^].



==== Suporte a volume de SnapLock

O Disaster Recovery agora oferece suporte a volumes de SnapLock, permitindo que você faça failover de snapshots à prova de adulteração.. Ao realizar o failback com volumes de SnapLock, você deve usar a opção *Take snapshot now* para garantir que o failback seja concluído com sucesso.

Para obter mais informações, consulte as instruções para link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["failover"^] e link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failback.html["failback"^].



==== Execuções simplificadas de atualização e conformidade

As execuções de atualização para vCenter, planos de replicação e conformidade foram simplificadas em uma única tarefa para facilitar uma execução mais rápida. Para ver essa alteração, aprenda como link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["monitorar trabalhos"^].



==== Verificações de conformidade do Kubernetes

O Disaster Recovery adicionou verificações de conformidade para identificar ambientes de trabalho ausentes para cargas de trabalho do Kubernetes. Essas verificações de conformidade ajudam a garantir a integridade dos seus planos de replicação para a integridade das cargas de trabalho.

=== Cloud Volumes ONTAP



==== Suporte para licenças baseadas em capacidade em implantações em modo privado

Agora você pode implantar o Cloud Volumes ONTAP em modo privado com licenças baseadas em capacidade na AWS, Azure e Google Cloud.

NetApp oferece suporte apenas ao pacote Essentials para o modelo de licenciamento baseado em capacidade no modo privado. Adquira um pacote Essentials BYOL (Bring-Your-Own License) baseado em capacidade da NetApp e atribua-o ao seu sistema durante a implantação. Os primeiros 500 GiB de capacidade consumida não são contabilizados no valor da sua licença. Você pode adquirir pacotes adicionais à medida que suas necessidades de carga de trabalho aumentam.

NetApp recomenda o licenciamento baseado em capacidade para todas as implementações do Cloud Volumes ONTAP em modo privado. Cada tarefa executada agora registra o usuário que a iniciou, fornecendo uma trilha de auditoria clara para fins de conformidade e solução de problemas. As tarefas acionadas automaticamente pelo NetApp Disaster Recovery são identificadas como "system", facilitando a distinção entre atividades iniciadas pelo usuário e atividades iniciadas pelo serviço.

Para mais informações, consulte link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["Monitorar trabalhos do NetApp Disaster Recovery"^].



==== Otimização de desempenho e recursos

Diversas melhorias internas foram implementadas para reduzir o consumo geral de recursos do sistema e aumentar o desempenho nas operações de NetApp Disaster Recovery.

==== Suporte a SAN para Google Cloud NetApp Volumes (prévia)

A Resiliência contra Ransomware agora oferece suporte a cargas de trabalho SAN do Google Cloud NetApp Volumes, permitindo que você detecte ataques de ransomware baseados em criptografia para cargas de trabalho SAN. O suporte para SAN no Google Cloud NetApp Volumes está atualmente em versão prévia.

=== Cloud Volumes ONTAP



==== Integração do Cloud Volumes ONTAP com o Microsoft OneLake

O Cloud Volumes ONTAP agora oferece suporte à integração com link:https://learn.microsoft.com/en-us/fabric/onelake/onelake-overview["Microsoft OneLake"^] em versão prévia pública. Você pode integrar o Cloud Volumes ONTAP com link:https://community.fabric.microsoft.com/["Microsoft Fabric"^] usando link:https://learn.microsoft.com/en-us/fabric/onelake/onelake-overview["Microsoft OneLake"^] para disponibilizar os dados NAS existentes do Cloud Volumes ONTAP para os serviços de análise e IA da Microsoft, como Power BI, Azure AI Search, OpenAI e Microsoft Copilot. A integração não requer movimentação de dados nem duplicação. A integração utiliza o acesso link:https://docs.netapp.com/us-en/ontap/s3-multiprotocol/index.html["ONTAP S3 multi-protocolo"^] para conectar o Cloud Volumes ONTAP a um lakehouse Microsoft Fabric existente.

==== Corrija, descarte e reative configurações para Cloud Volumes ONTAP no Microsoft Azure

O painel de controle bem estruturado no NetApp Console agora permite que você corrija recomendações de configuração para seus sistemas Cloud Volumes ONTAP.

Você também pode descartar uma ou mais configurações da análise de arquitetura bem estruturada. Isso permite ignorar configurações específicas que não se aplicam ao seu ambiente.

Se você quiser incluir uma configuração descartada posteriormente, poderá reativá-la no painel de controle bem arquitetado. Isso restaura a configuração à análise e permite que você receba recomendações e correções para ela.
